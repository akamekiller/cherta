# Черта — приложение для прописей китайских и японских иероглифов

Бесплатная альтернатива Skritter + Anki + Pleco. Автор — Влад, учит китайский (HSK) и японский (Genki).
Общаться с автором на русском. Интерфейс приложения — на русском.

## Цель
PWA (сайт, который ставится на телефон иконкой и работает офлайн). Основное устройство — телефон, письмо пальцем.
Позже, при необходимости, — обёртка в Android-приложение через Capacitor (код не должен этому мешать).

## Стек (как сделано сейчас)
- TypeScript без фреймворка, сборка через **esbuild** (`scripts/build.mjs`) в папку `site/`. `site/` хранится в репозитории и выкладывается на GitHub Pages как есть.
- Проверка черт: **hanzi-writer**, исходники лежат в `vendor/hanzi-writer` (MIT). Данные черт: Make Me a Hanzi из hanzi-writer-data (Arphic PL), нарезаны на 64 файла `site/data/strokes/NN.json` по коду символа (`scripts/build-strokes.mjs`).
- Хранилище: IndexedDB напрямую (`src/store.ts`, DB_VERSION 2): cards, reviews (журнал ответов), meta, edits (правки слов), userDecks (свои колоды). Версия схемы `DB_VERSION`, миграции в `onupgradeneeded`. Экспорт/импорт JSON есть.
- Планировщик: свой **FSRS-5** (`src/core/fsrs.ts`), параметры по умолчанию, шаги 1 и 10 мин, переучивание 10 мин.
- PWA: `static/manifest.webmanifest`, `static/sw.js` (оболочка — сеть, потом кэш; данные черт и шрифты — кэш, потом сеть). SW регистрируется только на https и localhost.
- Локальный сервер без зависимостей: `npm start` (`scripts/serve.mjs`), раздаёт `site/` на 0.0.0.0:5173.
- Тесты: встроенный `node --test` на TypeScript-файлах (Node 22.6+ со strip-types, Node 24 по умолчанию). Импорты внутри `src/` пишутся с расширением `.ts`.
- Карточки общие для всех колод: id = `zh:слово`.
- Почему не Vite: на старте работали из облака без доступа к npm. Переход на Vite возможен, если понадобится.

## Модули (порядок разработки)
1. **Карточки с проверкой написания** (MVP есть в `prototype/`). Показ значения → пишешь иероглиф(ы) в клетке 米字格 → вводишь пиньинь (`ren2` или `rén`) → авто-оценка → интервальное повторение. Озвучка после ответа.
2. **Тетрадь прописей.** Слева образец с анимацией порядка черт, справа ряд клеток: первые с бледным контуром, дальше пустые. Каждая клетка проверяется.
3. **Словарь.** Поиск по иероглифу, пиньиню/кане, русскому. Рукописный ввод для поиска (HanziLookup). Статья: слова с иероглифом, примеры, порядок черт, «добавить в колоду».
4. **Упражнения на перевод.** Предложения и диалоги RU→ZH (пишешь иероглифы от руки или с клавиатуры) и ZH→RU (сверка с эталоном и допустимыми вариантами). Уроки по уровням HSK, свои наборы.
5. **Тоны и произношение.** Цвета тонов везде; упражнения на слух (выбрать тон, пары тонов); проверка голоса: pitch-трекинг в браузере (YIN/autocorrelation через Web Audio), калибровка диапазона голоса, сравнение формы кривой с эталонами, график «твоя кривая поверх эталона». Позже — небольшая нейросеть на датасете Tone Perfect.

Японский — параллельно: кана + кандзи. Данные черт из KanjiVG нужно сконвертировать в формат hanzi-writer (strokes + medians). Порядок черт у общих иероглифов в Китае и Японии может отличаться — у каждого языка свои данные.

## Данные и лицензии
- Китайские черты: hanzi-writer-data (Make Me a Hanzi).
- Японские черты: KanjiVG (CC BY-SA 3.0).
- Словари: CC-CEDICT (CC BY-SA), JMdict/KANJIDIC (EDRDG, CC BY-SA). Русские: БКРС (китайско-русский), Warodai (японско-русский) — перед использованием проверить условия лицензий.
- Предложения: Tatoeba (CC BY 2.0 FR), пары zh–ru, ja–ru.
- Большие словари не класть в бандл: собирать скриптом в `scripts/` в шардированные JSON и грузить по запросу в IndexedDB.
- Колоды: новый HSK 3.0, `data/hsk3-N.tsv` (слово, пиньинь с цифрами тонов, русское значение) + список в `data/decks.json`. Слова и пиньинь — из github.com/drkameleon/complete-hsk-vocabulary (MIT, wordlists/exclusive/new), русские значения переведены Claude (возможны неточности). Уровни 1–6 готовы, 7–9 — в работе.
- Многозначные иероглифы: в исходных данных первым часто идёт редкое чтение/фамилия; 133 слова исправлены вручную по значению (读 dú, 说 shuō, 看 kàn, 长 zhǎng…). При добавлении новых уровней (7–9) проверять так же.
- Варианты тона через `/`, первый — основной для показа: `bu2/4` (不 перед 4-м тоном), `bu4/2`, `yi4/1/2` (一 перед 1–3-м), `yi2/1/4` (перед 4-м). Засчитываются все варианты.
- Сборка пишет `site/data/decks/index.json` (id, title, subtitle, count) — по нему строится выбор колоды на главной.

## Что уже перенесено из прототипа (`prototype/`) в `src/`
- Парсер пиньиня: принимает цифры (`ren2`), знаки (`rén`), `v`/`ü`/`u:`, слитно или через пробел; проверка по слогам, подсветка неверного тона.
- Расстановка знаков тона (правило a/e → ou → последняя гласная).
- Планировщик заменён на FSRS-5, интервалы Трудно < Хорошо < Легко гарантируются.
- Авто-оценка: «Не помню» или ошибок > 3×N → Снова; новая карточка с ≤N ошибками → Хорошо; подсказка или ошибок > N → Трудно; без ошибок → Хорошо; неверный пиньинь понижает оценку.
- Новые слова пишутся по контуру, повторения — по памяти. После 3 ошибок на черте hanzi-writer подсвечивает её.
- Дизайн: темы Авто/Светлая/Тёмная/Чёрная + «Своя» (`src/theme.ts`, редактор `src/ui/themeEditor.ts`: 11 цветов, скругление, предпросмотр, проверка контраста; производные токены считаются в `tokensFor`; своя тема хранится в settings.custom и в localStorage `cherta.custom` для применения до отрисовки), нефритовый акцент, цвета тонов (1 красный, 2 оранжевый, 3 зелёный, 4 синий, 5 серый), шрифты Golos Text / Noto Serif SC.

## Озвучка
- Основная: записи Kokoro-82M-v1.1-zh (Apache 2.0), голос **zf_047** (выбран автором), скорость 0.9, mp3 48k mono: `site/audio/zh/<слово>.mp3` + `site/audio/zh/index.json` ({voice, words}).
- Генерация: `tts/generate_all.py` (только новые слова, `--limit`), фонемы по пиньиню колоды — `tts/phonemes.py` (3-3 сандхи, эризация «r5» → R перед тоном). Запуск — GitHub Actions `.github/workflows/tts.yml` (сам при изменении data/*.tsv), порции по 1000 с коммитом после каждой, затем запуск pages.yml. Из облачной среды Claude Hugging Face недоступен — генерация только через Actions.
- `src/speech.ts`: сначала запись, если её нет — Web Speech API. SW кэширует mp3 после первого прослушивания.
- `scripts/build.mjs` не трогает `site/data` и `site/audio`.
- Адрес записи содержит `?v=<пиньинь>` из index.json: после переозвучки меняется, и офлайн-кэш (cache-first) не играет старый файл.
- Workflow коммитит в main → перед своим `git push` автору нужен `git pull`.

## Интерфейс
- Навигация: кнопка ☰ слева в шапке открывает боковое меню (`src/ui/nav.ts`): Карточки, Слова, будущие модули (с пометкой «Скоро»), Настройки. Закрывается по тапу вне меню, свайпу влево, Esc.
- Выбор колоды — раскрывающийся список в карточке колоды на главной.
- «Слова»: фильтры по статусу (Все/Новые/Учу/Повторяю/Скрыто), порядок (как в колоде — группы по 50; по пиньиню — группы по букве; по повторению — Сегодня/Завтра/…; сначала трудные), вид список/плитка, постепенная отрисовка по 100 при прокрутке. Выбор хранится в localStorage `cherta.words`.
- Поиск в «Словах»: сначала текущая колода, ниже «В других колодах» (все HSK).
- Озвучка переделывается для слов с изменившимся пиньинем: index.json хранит py каждого файла; `tts/redo.txt` — разовый список для файлов первого запуска.

## Редакторы (обязательно для каждого модуля)
- Принцип: базовые данные не меняются, правки пользователя хранятся отдельно и накладываются при показе; любую можно откатить. Правки входят в экспорт/импорт.
- Общий контейнер — панель снизу `src/ui/sheet.ts` (`openSheet`, `confirmInline`). Редакторы — `src/ui/editor.ts`.
- Слово: значение, пиньинь (`toNumeric` принимает «xué xí» / «xue2 xi2»), заметка-мнемоника, «скрыть из занятий». Логика — `src/core/edits.ts`.
- Свои колоды: строка иероглифов или «слово | пиньинь | значение»; недостающее подставляется из HSK (`hskLookup`).
- Список всех правок с кнопкой «Вернуть» — в настройках.
- Новый модуль = сразу свой редактор в том же стиле.

## Идеи, одобренные автором (внедрять по мере готовности модулей)
1. Отдельные карточки иероглифов из изученных слов (Skritter).
2. Разбор иероглифа на компоненты и мнемоники (Outlier).
3. «Пиявки» — слова с частыми провалами в отдельный список (Anki).
4. Ввод тона рисованием знака (Skritter).
5. Режим письма без подсказок, проверка после.
6. Персональная подстройка параметров FSRS по журналу reviews.
7. Серия дней и цель на день (Duolingo).
8. Статистика: календарь, прогноз нагрузки, точность, сколько иероглифов умею писать.
9. Тексты для чтения по уровню, тап по слову → перевод и «в колоду» (Du Chinese).
10. Аудирование: услышал — напиши.
11. Синхронизация между устройствами (например, приватный GitHub Gist).
12. Напоминания о повторении (насколько позволяет PWA).

## Правила работы
- Маленькие шаги: каждый шаг — рабочая версия, которую можно открыть на телефоне.
- Перед большими изменениями — коротко описать план автору.
- Чистая логика (пиньинь, FSRS, оценка, парсеры) — в `src/core/` с тестами; UI — в `src/ui/`.
- Коммиты небольшие, сообщения на русском или английском, понятные.
- Не ломать сохранённый прогресс: версия схемы данных + миграции.
- Проверять на ширине телефона (~375px) и в обеих темах.
