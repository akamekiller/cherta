# Черта — приложение для прописей китайских и японских иероглифов

Бесплатная альтернатива Skritter + Anki + Pleco. Автор — Влад, учит китайский (HSK) и японский (Genki).
Общаться с автором на русском. Интерфейс приложения — на русском.

## Цель
PWA (сайт, который ставится на телефон иконкой и работает офлайн). Основное устройство — телефон, письмо пальцем.
Позже, при необходимости, — обёртка в Android-приложение через Capacitor (код не должен этому мешать).

## Стек (как сделано сейчас)
- TypeScript без фреймворка, сборка через **esbuild** (`scripts/build.mjs`) в папку `site/`. `site/` хранится в репозитории и выкладывается на GitHub Pages как есть.
- Проверка черт: **hanzi-writer**, исходники лежат в `vendor/hanzi-writer` (MIT). Данные черт: Make Me a Hanzi из hanzi-writer-data (Arphic PL), нарезаны на 64 файла `site/data/strokes/NN.json` по коду символа (`scripts/build-strokes.mjs`).
- Хранилище: IndexedDB напрямую (`src/store.ts`, DB_VERSION 2): cards, reviews (журнал ответов), meta, edits (правки слов), userDecks (свои колоды). Версия схемы `DB_VERSION`, миграции в `onupgradeneeded`. Экспорт/импорт JSON есть (резервная копия всего прогресса — в настройках).
- Планировщик: свой **FSRS-5** (`src/core/fsrs.ts`), параметры по умолчанию, шаги 1 и 10 мин, переучивание 10 мин.
- PWA: `static/manifest.webmanifest`, `static/sw.js` (оболочка — сеть, потом кэш; данные черт и шрифты — кэш, потом сеть). SW регистрируется только на https и localhost.
- Японский шрифт Noto Serif JP (ofl/notoserifjp) — тем же `build_fonts.py`: 5 частей (сначала кана и знаки колод JLPT), `lang: "ja"` в files.json.
- Шрифты — свои файлы, не Google Fonts (в Китае без VPN не открывается): `python scripts/build_fonts.py <папка с ttf>` (ttf из github.com/google/fonts: ofl/golostext, ofl/ibmplexmono, ofl/notoserifsc; OFL 1.1; нужно `pip install fonttools brotli`) → `site/data/fonts/` (fonts.css, woff2 с хэшем в имени, files.json). Noto Serif SC (вес 500–700) нарезан на 7 частей по частоте знаков hw.txt (unicode-range, ~3,9 МБ всего), Golos и Plex Mono — латиница с пиньинем и кириллица, в оболочке SW.
- Локальный сервер без зависимостей: `npm start` (`scripts/serve.mjs`), раздаёт `site/` на 0.0.0.0:5173.
- Тесты: встроенный `node --test` на TypeScript-файлах (Node 22.6+ со strip-types, Node 24 по умолчанию). Импорты внутри `src/` пишутся с расширением `.ts`.
- Карточки общие для всех колод: id = `zh:слово` (навык «написание»), другие навыки — `zh:слово#read|tone|def` (`src/core/skills.ts`).
- Почему не Vite: на старте работали из облака без доступа к npm. Переход на Vite возможен, если понадобится.

## Порядок экранов (автор, 18.10.2026 вечер)
- Приложение открывается на «Словах» (словарь с поиском), а не на «Карточках». В меню «Слова» первым пунктом.
- Колоды сначала пусты: готовые добавляются из каталога («Готовые» / «Добавить готовые колоды»), `settings.added`. Убрать готовую колоду — «Убрать из списка» (прогресс по словам общий и остаётся). Миграция `migrateAdded` (один раз, когда `added` ещё нет): если есть карточки — остаются текущая колода, колоды с настройками, со счётчиком дня и все, где уже есть начатые слова. `app.deck` может быть `null` — везде проверять.
- Пикеры колод (тетрадь, тоны, своя практика) показывают только добавленные колоды.

## Модули (порядок разработки)
1. **Карточки с проверкой написания** (MVP есть в `prototype/`). Показ значения → пишешь иероглиф(ы) в клетке 米字格 → вводишь пиньинь (`ren2` или `rén`) → авто-оценка → интервальное повторение. Озвучка после ответа.
2. **Тетрадь прописей.** Готова: 10 клеток (3 по контуру), источник — любая колода или свой текст; печать A4/PDF.
3. **Словарь.** Поиск по иероглифу, пиньиню/кане, русскому, рисованием и голосом. Статья: слова с иероглифом, примеры, порядок черт, «добавить в колоду». Китайский — готов (大БКРС), японский — позже (Warodai).
4. **Упражнения.** Переделаны (см. раздел «Упражнения»): перевод на китайский (клавиатура, рукой, плитки), пропуски, аудирование, диалоги с вопросами; источник — колода, тема или свой набор из файла (уроки учебника).
5. **Тоны и произношение.** Есть: «На слух» (запись слова → тоны кнопками) и «Произношение» (микрофон → YIN → кривая поверх образцовых кривых тонов, примерная оценка по слогам). Позже — нейросеть на датасете Tone Perfect, точнее разбиение на слоги.

Японский — параллельно: кана + кандзи. Данные черт из KanjiVG нужно сконвертировать в формат hanzi-writer (strokes + medians). Порядок черт у общих иероглифов в Китае и Японии может отличаться — у каждого языка свои данные.

## Данные и лицензии
- Китайские черты: hanzi-writer-data (Make Me a Hanzi).
- Японские черты: KanjiVG (CC BY-SA 3.0) — сконвертированы (`scripts/build-strokes-ja.mjs`, `site/data/strokes-ja`), производные данные тоже под CC BY-SA.
- Словари: CC-CEDICT (CC BY-SA), JMdict/KANJIDIC (EDRDG, CC BY-SA). Русские: БКРС (китайско-русский), Warodai (японско-русский) — перед использованием проверить условия лицензий.
- Предложения: Tatoeba (CC BY 2.0 FR), пары zh–ru, ja–ru.
- Большие словари не класть в бандл: собирать скриптом в `scripts/` в шардированные JSON и грузить по запросу в IndexedDB.
- Старый HSK 2.0 (как в учебниках Standard Course): `data/hsk2-1..6.tsv` (150/146/298/597/1294/2483), `python scripts/build_hsk2.py <complete-hsk-vocabulary> [dict/]`: слова из wordlists/exclusive/old; если слово есть в HSK 3.0 — пиньинь и значение оттуда (2935), иначе чтение по БКРС и первое русское значение статьи БКРС (2033). Группа «HSK 2.0 — по учебникам», названия «HSK N (2.0)». Автор удивлялся, что в HSK 1 500 слов: это HSK 3.0, а 150 — старый стандарт.
- Колоды: новый HSK 3.0, `data/hsk3-N.tsv` (слово, пиньинь с цифрами тонов, русское значение) + список в `data/decks.json`. Слова и пиньинь — из github.com/drkameleon/complete-hsk-vocabulary (MIT, wordlists/exclusive/new), русские значения переведены Claude (возможны неточности). Уровни 1–6 готовы. 7–9 — **отложено** (20.10, автор: «7–9 особо нигде не требуют, это для тех, кто хочет знать больше»); делать только по его просьбе.
- Многозначные иероглифы: в исходных данных первым часто идёт редкое чтение/фамилия; 133 слова исправлены вручную по значению (读 dú, 说 shuō, 看 kàn, 长 zhǎng…). При добавлении новых уровней (7–9) проверять так же.
- Варианты тона через `/`, первый — основной для показа: `bu2/4` (不 перед 4-м тоном), `bu4/2`, `yi4/1/2` (一 перед 1–3-м), `yi2/1/4` (перед 4-м). Засчитываются все варианты.
- Сборка пишет `site/data/decks/index.json` (id, title, subtitle, group, count) — по нему строится список колод на главной (с заголовками групп).
- Колода «Ключи» (`data/radicals.tsv`, 197 строк): ключи и их формы (亻 氵 扌 讠…), чтение, значение и примеры иероглифов в скобках; всё есть в данных черт (нет только 牜 ⻊ — не включены).
- «Жизнь в Китае» (`data/life-*.tsv`): университет, общежитие, банк и деньги, транспорт, магазин и рынок, врач и аптека — по 33–37 слов. Составлены Claude; пиньинь сверен со словарём БКРС программно (все совпали, 13 слов в словаре нет). Озвучку новых слов сделает workflow после пуша.

## Словарь (大БКРС)
- Источник: база bkrs.info («базы можно использовать свободно в любых целях»), в интерфейсе подпись «Словарь 大БКРС» со ссылкой на статью. Файл `raw/dabkrs.gz` и частотник `raw/jieba-dict.txt` (dict.txt из github.com/fxsjy/jieba, MIT) в Git не хранятся (`raw/` в .gitignore).
- Сборка: `python scripts/build_dict.py [raw/dabkrs.gz] [raw/jieba-dict.txt]` → `dict/` (в .gitignore): `index.tsv` (слово, пиньинь БКРС, краткое значение; HSK, затем по частоте), `NNN.json` — 128 шардов статей (код первого символа % 128), `meta.json` (версия = хэш данных). Берутся слова jieba с частотой ≥ 5, все слова HSK, все иероглифы с данными черт и статьи, на которые они ссылаются «см.» (второй проход). ~106 тыс. статей, индекс 8 МБ (3,6 МБ в gzip), всё вместе ~35 МБ.
- Разметка DSL → HTML только из i, b, span.lb|c, a[data-w]; теги балансируются по строке; текст вне `[m]` тоже берётся; `\[ \]` раскрываются; ссылки на слова не из словаря — простым текстом. В приложении HTML ещё раз фильтруется `safeHtml`.
- `src/core/dict.ts` (тесты `tests/dict.test.ts` на выдуманных данных): `parseIndex`, `splitArticle` (значения отдельно, примеры под своим значением), `countWithChar`, `searchDict` (иероглифы: точное/начало/вхождение; пиньинь без тонов: точное/начало, учитываются все чтения; русский: значение целиком → целое слово → начало слова, внутри — порядок индекса), `wordsWithChar`, `dictPyToNumeric` (слитный пиньинь со знаками → формат колоды, деление на слоги по числу иероглифов, эризация → `r5`; разбирается 99,9%), `pyReadings`, `safeHtml`.
- Хранение: **отдельный репозиторий `akamekiller/cherta-dict`** со своим GitHub Pages (https://akamekiller.github.io/cherta-dict/), чтобы 35 МБ при каждой пересборке не копились в истории основного. Публикация — `powershell -ExecutionPolicy Bypass -File scripts\publish-dict.ps1`: один коммит с `push -f` (история не хранится); имя и почту для коммита скрипт берёт из основного репозитория (глобально git у автора не настроен). Скрипт в UTF-8 с BOM — иначе Windows PowerShell 5 ломает кириллицу.
- Загрузка — `dictIndex()` / `dictArticle()` в `src/state.ts`: на github.io берётся `DICT_REMOTE`, локально сначала `dict/` (его раздаёт `scripts/serve.mjs` из папки проекта), потом удалённый. Индекс — при первом поиске или открытии статьи, адреса с `?v=<версия>`; последняя `meta.json` хранится в localStorage `cherta.dictMeta` для офлайна. SW кэширует файлы словаря «сначала кэш» и удаляет старые версии того же файла.
- Важно при работе с данными: не выводить текст статей БКРС в чат/терминал — проверять программно, печатать только числа.

## Что уже перенесено из прототипа (`prototype/`) в `src/`
- Парсер пиньиня: принимает цифры (`ren2`), знаки (`rén`), `v`/`ü`/`u:`, слитно или через пробел; проверка по слогам, подсветка неверного тона.
- Расстановка знаков тона (правило a/e → ou → последняя гласная).
- Планировщик заменён на FSRS-5, интервалы Трудно < Хорошо < Легко гарантируются.
- Авто-оценка: «Не помню» или ошибок > 3×N → Снова; новая карточка с ≤N ошибками → Хорошо; подсказка или ошибок > N → Трудно; без ошибок → Хорошо; неверный пиньинь понижает оценку.
- Новые слова пишутся по контуру, повторения — по памяти. После 3 ошибок на черте hanzi-writer подсвечивает её.
- Дизайн: темы Авто/Светлая/Тёмная/Чёрная + «Своя» (`src/theme.ts`, редактор `src/ui/themeEditor.ts`: 11 цветов, скругление, предпросмотр, проверка контраста; производные токены считаются в `tokensFor`; своя тема хранится в settings.custom и в localStorage `cherta.custom` для применения до отрисовки), нефритовый акцент, цвета тонов (1 красный, 2 оранжевый, 3 зелёный, 4 синий, 5 серый), шрифты Golos Text / Noto Serif SC.

## Карточки и колоды (как в Anki и Skritter)
- Главная — список колод (`src/ui/home.ts`): столбцы Новые (синий) / Учу (красный) / Повтор (зелёный), тап — обзор колоды (view `deck`) с кнопкой «Учить», ⋯ — меню колоды: название, новых в день (своё для колоды), «Что тренировать» (навыки), слова колоды, экспорт в файл, удалить (своя) / скрыть (встроенная; «Скрытые колоды» внизу списка).
- Настройки колод — `settings.deckOpts[id]` (title, hidden, newPerDay, skills); счётчик новых за день — `day.byDeck[id]` (старый формат переносится в текущую колоду).
- Навыки (`src/core/skills.ts`, тесты `tests/skills.test.ts`): write — значение → иероглифы → пиньинь (оценка сама); read — иероглифы → вспомнить пиньинь и значение → «Показать ответ» → оценка себе; tone — иероглифы и значение → тоны жестом (буквы даны) → оценка сама; def — иероглифы и пиньинь → вспомнить значение; **recall** «Вспомнить слово» (0.33, автор: «как в Anki, без прописи») — значение → вспомнить иероглифы и пиньинь → «Показать ответ» → оценка себе. По умолчанию `DEFAULT_SKILLS` = write, read, tone, def (recall выключен, старые колоды не меняются). «Как учить» — чипы прямо на экране колоды (`renderSkills` в home.ts, сохраняются сразу, хотя бы один) и в меню ⋯; пропись можно выключить. Очередь `pickNext`: шаги заучивания → повторения → новое слово (лимит считается по словам) → новый навык начатого слова → шаги заранее.
- «↶ Отменить» в занятии (и Ctrl+Z) — возвращает карточку, журнал и счётчик дня (`undoAnswer`).
- Пиявки: слово забыто ≥ 4 раз хотя бы в одном навыке (`isLeech`) — метка в ответе с переходом к заметке-мнемонике, фильтр «Пиявки» в «Словах».
- Импорт/экспорт колод (`src/core/importer.ts`, тесты `tests/importer.test.ts`): текстовый экспорт Anki (#separator, #html, #deck), Pleco (TSV, //категории, пиньинь с цифрами слитно), CSV Skritter, любые таблицы (колонки определяются по содержимому), список иероглифов. Пиньинь нормализуется (`normalizePinyin`), недостающее берётся из HSK, затем из словаря. Экспорт — .txt с заголовками Anki (Файл → Импорт в Anki). .apkg не поддерживается (нужен SQLite).
- Несколько колод в одном файле (`parseImportAll`): разделы `## Название` (или категории Pleco `//Название`) — каждая своя колода; `#group:Имя` — группа в списке колод (поле `UserDeck.group`, сохраняется редактором). Окно импорта показывает список колод и поле группы.
- Группы в списке колод сворачиваются тапом по заголовку (`localStorage` `cherta.fold`, только на этом устройстве).
- Перо: толщина 50–160% (`settings.penSize`, `penShape(..., size)`), кисть максимум ~2 карандаша. Вибрация на ошибку (`settings.vibrate`).

## Упражнения — курсы (переделано 18.10 по просьбе автора: «как полноценный курс, а не библиотека»)
- Экран: «Мои курсы» → курс (уроки, «Продолжить: урок N», «Повторение пройденного», ⋯: «Слова курса — в колоды», убрать/удалить) → урок (шаги) → занятие. «Своя практика» — предложения корпуса под слова своей колоды (прежний режим, только добавленные колоды).
- Шаги урока (`STEPS`, `lessonSteps`, `stepTasks` в `src/core/exercise.ts`, тесты): Слова урока (список с озвучкой, «Учить карточками» → своя колода урока `u-c-<курс>-<N>` в группе курса, «Запомнил — дальше») → Узнавание (новый вид задания `word`: иероглифы → значение и значение → иероглифы, 4 варианта, `wordOptions`, `shortRu`) → Пропуски → Сборка фраз (плитки) → Аудирование → Перевод (ввод клавиатурой/рукой) → Диалог. Шаг засчитан от 70% (`PASS`), следующий открывается только после него (`stepOpen`). Лучший результат шага — meta `course` {ключ курса: {урок: {шаг: доля}}}, входит в резервную копию.
- **Без звука** (0.34, автор: «не всегда есть возможность прослушать»): кнопка «🔈 Без звука» на экране курса и урока (`ui.quiet` в localStorage `cherta.ex3`) — `lessonSteps(l, quiet)` убирает аудирование и диктант (`AUDIO_STEPS`), урок засчитывается без них; повторение пройденного — без аудирования (`reviewTasks(..., quiet)`).
- Рост сложности: пиньинь над словами — на курсе уровня 1 всегда, дальше только в первых шагах; лишних плиток больше с номером урока (1 + урок/5, до 3).
- Формат курса = прежний формат набора + `+ слово | пиньинь | значение` (слова урока, пиньинь цифрами или знаками — переводится `normalizePinyin`) + `#level: N`, `#about: текст`.
- Встроенные курсы — `python scripts/build_courses.py` → `data/courses/*.txt` + `index.json` (сборка копирует в `site/data/courses`, в офлайн-кэше): «Курс HSK 1/2/3» — свои темы уроков (`scripts/courses/hskN.txt`, все слова старого HSK N + несколько необходимых: 说 足球 对 天 饭 车 等 头 风), свои предложения и диалоги (`scripts/courses/hskN-text.txt`, скрипт проверяет, что в них только пройденные слова — печатает только наши тексты), предложения корпуса больше не берутся (0.30: там были обрывки и субтитры, `PER_LESSON = 0`) — только свои, 8–13 на урок, одно предложение — только в первом уроке, где встретилось; «Жизнь в Китае» — колоды life-* по два урока, свои предложения `scripts/courses/life-text.txt` (11–15 на урок, проверка: только HSK 1–3 старого + слова колоды), диалоги из data/dialogs.json. Подключённые встроенные курсы — `settings.courses`; свои из файла — meta `exsets`.

## Озвучка
- Основная: записи Kokoro-82M-v1.1-zh (Apache 2.0), голос **zf_047** (выбран автором), скорость 0.9, mp3 48k mono: `site/audio/zh/<слово>.mp3` + `site/audio/zh/index.json` ({voice, words}).
- Генерация: `tts/generate_all.py` (только новые слова, `--limit`), фонемы по пиньиню колоды — `tts/phonemes.py` (3-3 сандхи, эризация «r5» → R перед тоном). Запуск — GitHub Actions `.github/workflows/tts.yml` (сам при изменении data/*.tsv), порции по 1000 с коммитом после каждой, затем запуск pages.yml. Из облачной среды Claude Hugging Face недоступен — генерация только через Actions.
- `src/speech.ts`: сначала запись, если её нет — Web Speech API. SW кэширует mp3 после первого прослушивания.
- `scripts/build.mjs` не трогает `site/data` и `site/audio`.
- Адрес записи содержит `?v=<пиньинь>` из index.json: после переозвучки меняется, и офлайн-кэш (cache-first) не играет старый файл.
- Workflow коммитит в main → перед своим `git push` автору нужен `git pull`.
- Озвучка переделывается для слов с изменившимся пиньинем: index.json хранит py каждого файла; `tts/redo.txt` — разовый список для файлов первого запуска.
- Слоги a/o/e без начальной (爱 ài, 安 ān, 西安): в начале слова модель «придумывала» согласный (爱好 → «лэй хао»), поэтому перед ними в начале ставится пауза «,», в середине — « » (`tts/phonemes.py`, `needs_fix`). Такие слова в index.json помечены `|z` — по этой метке они переозвучиваются и обновляется кэш (?v=).

## Интерфейс
- Навигация: кнопка ☰ слева в шапке открывает боковое меню (`src/ui/nav.ts`): Карточки, Слова, будущие модули (с пометкой «Скоро»), Настройки. Закрывается по тапу вне меню, свайпу влево, Esc.
- Выбор колоды — раскрывающийся список в карточке колоды на главной.
- «Слова»: фильтры по статусу (Все/Новые/Учу/Повторяю/Скрыто), порядок (как в колоде — группы по 50; по пиньиню — группы по букве; по повторению — Сегодня/Завтра/…; сначала трудные), вид список/плитка, постепенная отрисовка по 100 при прокрутке. Выбор хранится в localStorage `cherta.words`.
- «Слова» (`src/ui/words.ts`) — два режима. Словарь (из меню, по умолчанию): поиск по всему 大БКРС одним списком (до 400, по 40 + «Показать ещё»), слова своих колод, которых нет в словаре, — сверху; метка — статус карточки или уровень HSK; без запроса — «Недавно открытые» (localStorage `cherta.recent`) и ссылка на слова текущей колоды. Слова колоды (`openDeckWords()` из обзора и меню колоды): прежний список с фильтрами и порядком, поиск внутри колоды и «Искать во всём словаре». Рядом с полем — «нарисовать» и «голос».
- Карточка слова (`src/ui/entry.ts`): шапка слева — иероглифы, пиньинь (другие чтения 多音字 — «также …»), краткое значение, метки (уровень HSK, статус), «+ В колоду» и «Изменить»; ниже липкие вкладки **Значения · Примеры · Слова · Черты**. Значения — до 12 строк + «Показать всю статью»; Примеры — под своим значением, 8 + «Все примеры»; Слова — плитки, фильтр «Начинаются с X / Все с X», выбор иероглифа слова, 18 + «Показать ещё»; Черты — поле с порядком черт (создаётся при открытии вкладки). Ссылки «см.» и плитки открывают слово, «← Назад» возвращает по цепочке. Источник «Статья из словаря 大БКРС» со ссылкой на bkrs.info.
- Общие для списка и карточки функции (слова не из колоды, статус, строка списка) — `src/ui/lookup.ts`.
- «+ В колоду» и «Изменить» — для любого слова; если пиньинь БКРС не разобрался или нет значения, панель просит их ввести. Редактор своей колоды ищет и по словарю (после HSK).

## Пиньинь в карточках
- После того как иероглифы написаны, кнопки «контур / не помню» сменяются вводом пиньиня (`src/ui/pypick.ts`, логика `src/core/pypick.ts`, тесты `tests/pypick.test.ts`): ячейка на каждый слог; слог выбирается из 6 вариантов (верный + похожие по начальной/конечной части: zh/z/j, an/ang…; стабильны для слова), тон — жестом по полосе тонов (ровно 1, вверх 2, провал 3, вниз 4, касание — знак под пальцем) или нажатием знака. Полоса нормируется по ширине (×2), чтобы наклон считался как на квадрате.
- «Набрать с клавиатуры» (0.33, автор: «пиньинь клавиатурой, а тон — кнопкой»): набираются буквы (`xuexi`, цифры и знаки тоже понимаются), `splitTyped` (`src/core/pypick.ts`) делит их на слоги (по пробелам → по эталону → на настоящие слоги → поровну), тон каждого слога — той же полосой тонов. Enter без тонов прячет клавиатуру. У навыка «Тоны» — всегда кнопки. Выбор хранится в localStorage `cherta.pyMode`. Проверка та же — `checkPinyin`.
